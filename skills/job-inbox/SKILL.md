# Inbox

Use the available authorized inbox and current pipeline. Search by company,
role, requisition, known contact, ATS sender and relevant date window. Widen
when the initial search misses plausible results. Read the thread, not just a
subject or snippet. Account access alone does not define the requested task.

Match using application/requisition links, employer plus role, known recruiter
or prior thread context. A generic ATS domain or agency name is insufficient.
Keep ambiguous messages in private unmatched notes with possible jobs and the
missing evidence; don't lose them or assign an arbitrary stage.

Distinguish receipt confirmation, marketing, a recruiter reply, interview,
rejection and offer. Use `note`, `mark` and outreach state only for events the
message supports. Preserve source/date and exact deadlines. A rejection for one
requisition need not close a different application at that employer.

Lead with what needs action and by when. Write requested replies using
candidate-voice and confirmed availability. Use existing sending authorization;
a read-only check does not imply a reply request. Mail organization is a separate
user choice, not an automatic side effect of matching messages. Save the next
search window and unresolved threads so future reconciliation has continuity.
